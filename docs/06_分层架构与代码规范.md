## 2. 依赖规则(核心; 2026-11-13 按 docs/17 §2.2 修订, 与 check_layers.py 实现一致)

1. **任何层都可依赖 L0**(基础件是全树公共底座);
2. **上层只依赖下层稳定公开接口, 允许跨层**(跨空层/直达公开 API), 且只准用对方
   `include/` 下的公开 API; 同层只放行公开头, 私有/实现头不在公开集天然不可达;
3. **禁止向上依赖**(任何 Lx → Ly(x<y) 一律报错);
4. **L4 表现特例**: 不依赖任何 L1-L3 固件组件, 只依赖 `ui_model.h` 契约
   (固件/模拟器链接期绑定后端);
5. **L5 装配 → 全部**(它是唯一合法的"知道所有人"的位置);
6. **同层协作约定**: 控制面/状态面优先走 cubecore 事件总线(小型通知);
   可靠命令/回执走向下依赖的契约与注入端口, 不用同层私有头形成网状依赖;
   音频数据面单向流入 app_audio(唯一汇聚点);
7. **未知组件报错**: 未在层表登记的组件一律构建失败(先登记再写代码);
8. 头文件被谁 include 就必须在谁的 REQUIRES/PRIV_REQUIRES 里声明(CMake 与源码一致)。

### 2.1 UI 边界的特殊性(双后端)

`app_ui/ui/ui_model.h` 是 L4 与 L3/L2 之间的**契约层**: UI 代码(固件/模拟器同源编译)
只 include `ui_model.h`, 后端在 L5 实现:

- 固件: `main/ui_port_esp.c`(事件总线→快照, ui_ctl_*→audio_mixer/app_player/...);
- 模拟器: `sim/src/mock_app.c`(合成音频/BT/歌词时间线)。

线程契约: 快照单写者; 字符串写入须与 UI 任务互斥(设备侧 lvgl_port_lock);
UI 在 LVGL 定时器里轮询快照, 无事件回调、无锁。

## 3. 麦克风所有权协议(L2/L3 特例约定)

`audio_mic_read_16k()` 为**单消费者拉取**接口, 同一时刻只允许一个任务调用:

| AI 会话状态 | 麦克风消费者 | 说明 |
|---|---|---|
| IDLE(无会话) | app_voice | WakeNet 连续检测 |
| LISTENING | app_ai_session | ASR 采集(voice 暂停, 订阅 CUBE_EVT_AI_STATE) |
| THINKING/SPEAKING | app_voice | 恢复检测, 供 barge-in 再唤醒打断 |

切换由 app_voice 订阅 `CUBE_EVT_AI_STATE` 自主完成, 无中心仲裁者。

|---|---|---|
| `cube_` | L0 cubecore | cube_event_publish / cube_resampler_init |
| `BOARD_` | L0 boardcfg 宏 | BOARD_PIN_I2S_MCK |
| `drv_` | L1 驱动 | drv_audio_init / drv_display_get_panel |
| `audio_` | L2 app_audio | audio_mixer_add_source / audio_mic_read_16k |
| `app_net_` / `app_bt_` / `app_player_` / `app_voice_` | L3 应用 | 各自组件头 |

- 文件内私有: `static` + 短名; 跨文件模块内共享: `static` 结构体归组后放 `xxx_internal.h`;

## 6. 错误处理规范

1. **组件内**: `ESP_RETURN_ON_FALSE/ON_ERROR`(esp_check.h), 错误路径必须释放已持资源;
2. **装配层 main**: 失败域三档, 写明每档理由——
   - 音频链路(drv_audio/mixer): 核心功能, 失败 abort(但 PA 必须在 mixer start 成功后才开);
   - 显示/网络/蓝牙/语音/AI: 独立失败域, 失败降级(日志+关闭该功能), 绝不 abort;
3. **任务函数**: 禁止 return 退出, 统一 `goto err` + 资源释放 + `vTaskDelete(NULL)`;
4. **中断/网络回调上下文**: 不阻塞、不持锁、只投队列/写环形缓冲。

## 7. 任务参数规范

全机任务的名字/栈/优先级/绑核集中登记在 `cubecore/include/cube_tasks.h`(单点可查),
组件用宏创建任务。优先级全局序(高→低):

```
mixer(20) > voice(18) > player(12) > ai(5) > LVGL(4)
```

音频实时 > 唤醒检测 > 流解码 > 云端会话 > UI 渲染。

**栈放置(2026-11-18 预算批次, v6.1 板上实证口径)**: 任务栈位置四分类——HP DRAM 静态
(mixer/voice/aisess/aremind)、**RTCRAM 定置 .rtc.bss**(cli/soul/think, 非 DMA/非 PIE/非实时)、
PSRAM(player 双槽静态/faceload/skpf/pstart/psoul/psnsd/**aitts/aimic**, WithCaps)、
内部动态(库创建或实证约束: taskLVGL DMA caps、pairsrv 禁 PSRAM)。判定规则与预算表见
docs/22; **新增任务先入 docs/22 预算表再写创建代码**(cube_tasks.h 头部同款规则,
host_tests 附块 map 校验把关)。

## 8. 性能红线关联

全屏 460×460 稳定 30fps(docs/01 §1.3)。UI 渲染热路径预算 ≈ 8ms(S31 口径),
每帧循环内禁止: 整数除法(改倒数表/移位)、逐像素 sqrtf(改预渲染 sprite 或平方
比较)、全画布 memset(改脏带清理)、逐帧 powf(改启动预计算表);
超过 4KB 的每帧分配必须池化复用(如歌词 snapshot 双缓冲)。

## 9. 双目标/双板适配矩阵(S31 + P4C5, 2026-11-11)

同一代码库支持两块板, 全部差异收敛在**配置层与 L0/L1**, 上层业务零感知。

### 9.1 板卡概览

| | EspCube S31 板 | 鱼鹰 OSPTEK P4C5 板 |
|---|---|---|
| 芯片 | ESP32-S31-WROOM-3 (BT+WiFi) | ESP32-P4 v3.2 + ESP32-C5 共芯 |
| 屏 | 2寸 460×460 CO5300 **QSPI** (AM200Q…FLS1) | 同面板 **MIPI-DSI** 版 (AM200MT…FLS2, 1lane@330Mbps) |
| WiFi | 原生 esp_wifi | esp_hosted 3.0.10 over C5 SDIO(透传, API 不变) |
| 蓝牙 | A2DP Sink(可用) | 无(芯片无 BT 控制器) |
| 音频 | ES8311+NS4150B(同款) | ES8311+NS4150B(同款, 引脚不同) |
| Flash/PSRAM | 16MB / OCT 16MB | 16MB Boya / HEX 32MB |

### 9.2 配置文件布局(IDF 原生机制)

```
firmware/sdkconfig.defaults             # 公共(网络/LVGL/看门狗/日志)
firmware/sdkconfig.defaults.esp32s31    # S31: BT/coex/OCT PSRAM/BT 缓冲调优
firmware/sdkconfig.defaults.esp32p4     # P4: HEX PSRAM/CACHE_64B/no-stub/
                                         #     分区表@0x10000/hosted/C5 目标
firmware/partitions.csv                 # S31 布局(表@0x8000)
firmware/partitions-p4c5.csv            # P4 布局(表@0x10000, 同构)
firmware/sdkconfig                       # S31 本地(gitignored, 含凭据)
firmware/sdkconfig.p4c5                  # P4 本地(gitignored, 含凭据)
```

构建口径(构建目录与 sdkconfig 一一对应, 互不干扰; 2026-11-14 补 build-s31):

```bash
idf.py --preview -B build-s31    build   # S31(批次 17 起独立目录+独立 sdkconfig)
idf.py -B build-p4c5 -DSDKCONFIG=$PWD/sdkconfig.p4c5 build   # P4
idf.py -B build-p4c5 -p /dev/ttyACM0 -b 230400 flash monitor # P4 烧录(no-stub)
```

⚠ 注意: **勿在工程目录裸跑 set-target** —— 会重写 `firmware/sdkconfig`。
P4 一律带 `-DSDKCONFIG=…/sdkconfig.p4c5`。

### 9.3 差异收敛点(代码侧)

| 差异 | 收敛位置 | 机制 |
|---|---|---|
| 引脚/板级常量 | `boardcfg/include/board_pins_{s31,p4c5}.h` | Kconfig `ESP_CUBE_BOARD` choice(随 target 默认), `board_pins.h` 分派 |
| 显示接口后端 | `drv_display_qspi.c` / `drv_display_dsi.c` | CMake 按 `IDF_TARGET` 选源; `app_ui_boot_cfg_t.iface` 决定 LVGL 绑定方式(QSPI 全帧双缓冲+swap / DSI direct_mode+avoid_tearing) |
| 蓝牙有无 | `CONFIG_ESP_CUBE_ENABLE_BT`(仅 S31 存在) | app_bt 全文件守卫 + app_player/app_net BT 段 `#if`(P4 上 bt_pause_gate 空实现) |
| WiFi 通道 | `CONFIG_ESP_CUBE_NET_HOSTED`(默认 y 于 P4) | app_net 两段式 esp_hosted 初始化分支 |
| I2S DMA 形状 | `BOARD_AUDIO_DMA_*` | S31 6×240 / P4C5 8×480+auto_clear |
| PA 怪癖 | `BOARD_AMP_MANUAL_PA` | P4C5: codec open 后手工补配推挽 |
| esp_codec_dev | **双目标统一 1.6.2** | 单工程共享 managed_components, 不支持按 target 双版本(manifest `matches` 会互相覆写) |

### 9.4 新板接入清单

1. `boardcfg` 加 `board_pins_<板>.h` + Kconfig choice 项;
2. `sdkconfig.defaults.<target>` + 分区表(必要时);
3. 显示后端: 已有面板 IC 驱动 → `drv_display_*.c` 新增; 否则走 esp_lcd 组件;
4. `tools/check_layers.py` 跑一遍(板级头不得引入新的跨层 include)。

### 9.5 表情动画(esp_efc_codec 1.1.0 + lv_efc, 2026-11-15 裁决由 EAF 改回 EFC)
- **演进**: 原方案为 esp_efc_codec 1.1.0(EFC, §22 批次 7 集成)。批次 38 换装 EAF(`esp_lv_eaf_player`)后, 素材调色板 alpha 全为 0, 整帧透明并黑屏(docs/19 §44、§46)。2026-11-15 用户裁决改回 EFC, EAF 路线退役。
- **美术来源**: 乐鑫官方 Emote Pack 的 848×848 GIF, 为唯一输入。个人 DIY 非商业用途, 仓库若对外公开需复核。
- **EFC 管线**: `tools/efc_build.py` 在 PC 侧按 100 ms 采样、等比缩放到 460×460、键控色 0xF81F、tile 4、zlib 编码, 写出 `<name>.efc` 与 `MANIFEST.json`。`tools/efc_verify.py --contract` 检查 magic `EFC1`、尺寸、帧数、键占比与透明像素。
- **素材布局**: `app_ui/ui/assets/face/` 保存 23 段候选池(合计 206,846 字节, 最大 44,565 字节)。固件只内置 smile_static、laugh、investigate、shocked 4 段(合计 29,641 字节)。SD 只承载覆盖文件 `face/idle.efc` 与 `face/<name>.efc`。
- **开关**: `CONFIG_ESP_CUBE_ENABLE_FACE_ANIM`(P4 默认开, S31 与 sim 门关)。表情关闭时不链接 esp_efc_codec(需求 3.21)。
- **承载(已实施, v5)**: `lv_efc` 对象 460×460 居中; 挂起/恢复统一 `ui_face_set_running()`, splash 与面板展开时暂停。
- **⚠ PIE 架构不变量(v5, docs/19 §52 根因)**: esp_efc 解码使用 PIE 向量协处理器, 其上下文保存区 carve 在**执行任务自己的栈底**, 而 PIE 向量存储(esp.vst)不能写 LP SRAM(RTCRAM)。因此:
  1. **taskLVGL 栈必须 `MALLOC_CAP_INTERNAL|MALLOC_CAP_DMA`**(esp_lvgl_port 的 `task_stack_caps` 字段; DMA caps 精确排除 RTCRAM), 栈 20480B(§52 实测 pre_ui 最大连续块 23552~25600);
  2. **所有 EFC 解码只允许在 taskLVGL 执行**——其他任务(SD 热载/faceperf 切片)经 `ui_face_exec_in_lvgl()`(lv_async_call+信号量, ui_port_esp.c)转投; CLI 等任务不得直接调 lv_efc_set_src_data/esp_efc_dec_*;
  3. 新增会执行 PIE 的代码路径时必须遵守本条(违者 ~1.6s 后 WDT 复位)。
- **性能(2026-11-18 实测, 方法学=平台上限 1000/T 去 delay 定帧)**: 复杂片段 P95 口径 22.0~23.6fps(要求 ≥15 ✓);
  简单片段 P50 36.5~37.3fps/P95 21.7~24.4fps(要求 ≥30——P50 达标, P95 尾源=LVGL loop 抖动 I_loop P95 44ms,
  非解码 D P95≤22ms; 30fps@P95 属 loop 抖动优化专项)。旧 33/66ms 帧时预算口径作废(docs/19 §1)。

## 10. 网易云音乐游客音源(app_ncm, L2, 2026-11-11)

- **组件**: `components/app_ncm`(L2 云服务协议库, 同 speech_provider 定位) ——
  weapi 加密(`ncm_weapi.c`: AES-128-CBC×2 走 PSA Crypto + RSA-1024 裸模幂走
  bignum MPI, ⚠ include 顺序: bignum.h 必须先于 psa/crypto.h, 见源注释) +
  搜索/取址(`app_ncm.c`: esp_http_client + cjson)。API 同步阻塞, 仅任务上下文调用。
- **口径**(2026-11-11 板上与 PC 双端验证): 游客无需 cookie; UA=Edge/Chrome;
  播放地址**剥离 query**(vuutv 为网页端校验参数, 非 app 客户端携带被 CDN 403);
  URL 有效期约 20 分钟现取现播; 游客仅 fee=0/8 曲目(VIP 曲需二期登录)。
- **编排**: L5 `main/cli.c` 串口命令(`ncm <关键词>`/`ncmn <n>`/`radio`/`st <n>`) →
  app_ncm 取 URL → `app_player_start(url)` 单曲直播(direct_stream+minimp3 垫片,
  零改动)。CLI 输入通道: UART0 仅装 RX 驱动直读, TX 保持 esp_stdio 直写
  (uart_vfs_dev_use_driver 在 IDF6 控制台会 vfprintf 递归爆栈, 勿用);
  UTF-8 中文关键词直通。
- **合规/风险**: 第三方逆向接口(社区维护, 8821/vuutv 均为网易收紧痕迹),
