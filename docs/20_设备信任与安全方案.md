# 20 · 设备信任与安全方案(T14 落地设计)

> 版本：v1.0｜2026-11-13｜上游：[17 §8.3/§9](17_系统软件详细设计.md)、[16](16_产品需求规格与功能边界.md)§6/§7｜验收：docs/18 T14(R/H)
>
> 原则：**先软件方案(M1)落地，硬件硬化(M2)需单独授权**——eFuse 烧录不可逆，不擅自操作。全部方案以"可实施"为准：具体到密钥生成、存储位置、协议流程、失败语义；不虚称硬件防护已开启（docs/15/17 已核实的边界）。

## 1. 威胁模型(操作分级)

| 攻击者/风险 | 能力 | 现状暴露 | 防线归属 |
|---|---|---|---|
| 同网攻击者 | 扫描/连接设备端口、重放、伪造 App | 管理通道未建(T17); 电台 HTTP 明文(既有) | §4 配对+管理通道 |
| 拔 SD 物理访问 | 读/复制/篡改 SD 文件 | registry/记忆目前**明文** | §5 SD 加密(限内: SD 可拔走即带走, docs/09 既有口径) |
| 拿到设备本体 | 上电读串口/触发台调 | CLI 仅串口物理可达; psnclear 等台调命令可清资料 | 串口物理访问≈用户(现有假设), M2 可收紧 |
| 云服务商 | 见服务条款 | 用户自备凭据, 发送范围已声明(FR-04) | 合同层, 非本方案 |
| 日志泄露 | 读串口/日志文件 | 原文不落日志(既有纪律); 凭据不回显 | 维持+§7 审计 |
| 失钥 | 设备密钥/SD 密钥丢失 | 无密钥机制(现状) | §6 恢复语义 |

**不做/不虚称**：防拆封探针、侧信道防护、介质级擦除保证（A-11 口径）。

## 2. 设备身份与密钥(M1 软件方案)

| 密钥 | 生成 | 存放 | 用途 |
|---|---|---|---|
| 设备身份密钥 `dev_key` | 首次启动 `esp_random()` 生成 256bit | NVS `trust/` 命名空间（写入后不再读出接口——存即用哈希校验? 简化: 可读但仅管理通道使用） | 管理通道 mTLS 证书体系根密钥/凭据域 HKDF(credstore dev_key 域)/配对挑战 |
| SD 记忆密钥 `sd_key` | 首次启用记忆时生成 | NVS `trust/`；**不随 SD 走**——换卡/拔卡数据不可读(密钥在设备) | §5 记忆文件 AES-GCM |
| 每文件密钥 | HKDF(`sd_key`, persona_id+文件名) | 派生不存储 | per-persona 隔离加密 |

- NVS `trust/` 命名空间**不加 NVS 加密前的威胁声明**：能物理读 flash 者可提取（M1 边界，如实声明）；M2 flash encryption 上线后自动覆盖。
- RNG：`esp_random()` 硬件 RNG（WiFi/hosted 使能后熵充足；首次启动在联网前——boot 时熵源为混合，密钥生成挪到 SD ready/联网后执行一次，避免弱熵）。
- **eFuse 一律不动**(M1)；M2(flash encryption+secure boot+NVS 加密)独立方案需用户单独授权烧录，属不可逆操作。

## 3. 信任根缺失下的首配(M1)

无硬件信任根时首配的诚实目标：**绑定第一台物理接触的 App**（近场假设——攻击者须在配对窗口内同网且无人在场）。

1. 设备屏幕显示 6 位数字码（`esp_random` 生成，120s 有效）+ 触摸"确认配对"发起。
2. App 扫码/手输 → 通过设备 SoftAP 或局域网 HTTPS(no mTLS 阶段) 发起配对：SRP-6a（PIN 作为口令，防离线字典——PIN 高熵 6 位数字+限速 5 次/窗）。
3. 成功后交换：App 生成客户端密钥对，设备记录公钥指纹 + 签发 `client_id`；此后管理通道 = TLS + 客户端证书（mTLS），设备侧校验已配对指纹表。
4. **多 App/换机**：新配对需设备端触摸确认（旧 App 收到变更通知）；撤销 = 删除指纹。
5. 失败语义：PIN 错 5 次 → 窗口作废重生成；窗口外请求拒绝。

## 4. 管理通道(落地到 §9.3 REST)

- **自管 TLS 监听任务（esp-tls 直用）+ mTLS**（CA=主机预置 openssl 自签, 客户端证书=配对时签发）——**版本化 v1 接口全部走此通道**，明文 HTTP 不开。（2026-11-14 附注: 原方案 `esp_https_server` 已在批次 19 因 mbedtls 4 pk API 私有化弃用, 改自管 TLS 监听; **证书为主机预置**(tools/gen_pair_certs.sh), 设备端签发(PSA+自建 DER)归 M2 专项——见 docs/19 §24。）
- 未配对设备仅暴露：配对端点(SRP)+只读 `/v1/device` 基本状态（无敏感字段）。
- 证书校验不过/未配对客户端 → 401/403, 不泄露字段差异。

## 5. SD 记忆加密(认证加密格式 v2)

替换 §8.1 工作假设（明文 TSV）→ **加密容器**，personas 与记忆文件统一：

```text
文件 = [8B magic "EPSCV2"][24B nonce][密文][16B GCM tag]
密文 = 原格式(registry 双槽载荷 / episodes.tsv / deleted.log)
密钥 = HKDF-SHA256(sd_key, salt=整个 24B nonce, info="epsc/<rel>")
nonce: 24B 全随机(每写新, esp_random); 无计数器(写频率低, 随机 nonce 不复用);
       前 12B 兼作 GCM nonce, 整 24B 兼作 HKDF salt
```

- 算法：mbedtls AES-256-GCM（IDF 内置已链接 esp-tls）；不自造密码学。
- 读：解密失败(tag 不符) → 该文件视为损坏 → 双槽回退另一槽/RECOVERY_REQUIRED（沿用 §8.2 状态机，不新增分支）。
- **台账(deleted.log)同步加密**——防攻击者读删除历史。
- registry(角色底座)同样加密——角色描述属用户内容。
- 首次启用：`sd_key` 生成即升级；**旧明文文件迁移**=读旧→写新→删旧（一次性，T20 已授权清场，实测卡已空）。
- 边界如实：SD 拔走+设备也在手 → 可读（密钥在设备）；仅防"只拿 SD"。

## 6. 失钥与恢复语义

| 失钥 | 后果 | 恢复 |
|---|---|---|
| sd_key 丢（NVS 损坏/清除资料） | SD 记忆全部不可读 | 按已授权清除流程处理（无云备份=设计边界） |
| dev_key 丢 | 配对关系失效 | 设备端物理入口重置+重新配对（清信任区） |
| 恶意清除信任区 | 配对/密钥重置 | 等于恢复出厂——App 旧关系失效并通知 |

## 7. 台调命令(M1 配套)

- `trust stat`：信任区/密钥存在性(不打印密钥)/SD 加密状态/配对客户端数。
- `trust reset`：清信任区（不可逆，串口物理确认）。

## 8. M2 硬件强化(独立授权项, 不在本轮实施)

flash encryption(Release)+secure boot+NVS 加密——收益：物理读 flash 不可得明文/固件不可篡改；代价：eFuse 不可逆、开发烧录流程改变、恢复受限。触发条件：转向多台/交付部署时。**决定权在用户**，方案另出专项。
