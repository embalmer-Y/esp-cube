## 1. 产品定义

### 1.1 定位

EspCube 是可放在桌面的 AI 伙伴：具有可配置角色、持续对话、经许可的记忆和受控成长，并能结合自身状态、情境、记忆、用户意图与可用能力决定行动。电台、歌曲、声音和表情是它可以调用的能力，**不是独立产品中心**。

自主搭话、播放音乐、显示表情只是同一行为框架可产生的不同动作。新增一种执行能力时，应通过能力声明、授权与执行回执接入，而非再复制一套特定功能的“自主动机模块”。AI 原则上可参与所有已注册能力的选择、参数配置和组合；但不能绕过用户控制、权限、安全规则或资源限制，更不能因此执行任意代码。

### 1.3 不纳入本轮已确认的首版验收

- S31 同步交付、P4 经典蓝牙音频、iOS、公网账号系统、远程管理、云同步/云备份。
- 完整离线对话/音乐/助手；“麦克风停止会话录音”也不等于关闭唤醒监听或物理断电。
- 声纹鉴别、多用户身份推断；保留此前确定的**客户自定义/声音复刻方向**和现有工具，但其具体产品交互、云服务授权与交付时点尚未确定，本轮不擅自裁定是否为首版必交；已确定预设男/女音色和 `longanrou_v3` 默认目标。
- 日常助理作为必交范围、完整商业曲库分发授权、任意模型/任意第三方唤醒模型直接可运行。
- 真实意识、生理饥饿或疲劳、情绪识别真实性等不可验证的拟人化宣称。

## 2. 已确认的行为与数据原则

### 2.1 自主不是三个功能的集合

1. **决策依据不限于情绪。**用户显式意图、当前会话、记忆来源和相关性、人物设定、已形成的偏好、互动历史、环境/设备事实、资源、网络与时间共同提供可用信号；未知就是未知。
2. **能力通用。**AI 可以在声明过的能力及有效参数空间中决定做什么、怎么做及如何组合；没有能力或授权时返回原因，不能凭空声称完成。添加未来能力不需要改动整个决策器。
3. **用户方向盘优先。**用户主动说话、暂停/停止或指定音乐、音量等操作不能被自主行为立即撤销。设备安全和必须遵守的隐私规则始终生效；用户要求本身也必须经过适用的授权与资源检查。
4. **默认开启不是开机强制播歌。**是否搭话、何时播放/切换音乐和表情应进入统一候选与情境判断。启动、重连不能绕过自主总开关、用户上一次停止及统一仲裁。
5. **勿扰默认不启用。**若用户之后启用并设定时段，在时钟无效时只对受该规则约束的**新自主出声**采用保守策略；不能靠勿扰擅自停掉用户明确开启的播放。
6. 允许用时间预算和频率上限防止误触发或资源耗尽；数值是**设计假设、可配置且需实测**，不是脑科学事实或用户已经选择的固定习惯。
7. **行为来源原则（2026-11-19 用户裁决）**：设备不内置任何"条件→行为"的生成规则；做什么只来自用户决策与 AI（深思）主动决策。本地系统只负责表达（表情/韵律/措辞）、决定何时深思与执行约束（预算/勿扰/停止锁存/礼貌）。开机、联网、重连不自动播歌。性格演化（trait 层）立项：经授权的有界慢变，用户可查看依据、暂停、回滚，详见 [17](17_系统软件详细设计.md) §7.4 与 [24](24_灵魂层v2设计定案.md)。

### 2.2 人格与演化

- 角色卡是经用户确认的角色底座；AI 生成只是草稿，显示来源并经用户确认后生效。
- 在授权和边界内，可自主调整语言表达、动作/表情偏好、话题/音乐兴趣、主动互动风格；这些是首版初始支持的变化类别，不是未来动作的封闭清单。
- 将伙伴自己的兴趣与用户已确认的偏好分开；推测不能替代用户明确表达，也不能被当作客观心理评估。
- 用户可查看变化及其依据、暂停/恢复和回滚；未经重新授权不能修改隐私、安全设置、服务凭据或用户锁定的角色配置。个别低风险变化不要求逐次确认。
- 切换角色时，长期记忆、派生摘要/索引、工作上下文、行动提议、演化版本与在途云结果均按角色和代次隔离。

### 2.3 记忆、身份与录音

- 经同意自动形成**摘要级文字**事件和偏好；常规会话上下文只在内存中按需保留，不默认形成录音或完整原始对话日志。现有截断原话实现不能被当成满足该要求。
- 本地存储与云传输分开说明：语音识别/对话以及已授权的云端记忆提炼可能把相关音频或文本发给用户配置的服务商；不能因为“不保存录音”就声称“不上传音频”。服务商留存政策、计费和删除方式以其实际条款为准。
- 不把模型推断出的事实直接当用户确认；来源、角色、可信状态与时间随记录保存。敏感内容需要额外确认；凭据与密钥不得写入长期记忆。
- 单用户优先不等于识别了说话者：默认语音来源标记为未验证，低风险对话可以进行，但删除记忆、修改凭据/隐私等管理操作要求已配对 App 和相应确认。
- 立即从使用层撤销已删除信息；设备可报告本地逻辑删除和清理进度，但不能承诺已发往服务商的内容被撤回，也不能仅凭文件删除承诺 SD 闪存的物理擦除。

“完成定义”中的“可证明/通过”指未来实施后的验收标准，不表示现在已满足。

| FR-27 | 敏感信息保护。 | 对可能敏感的记忆额外确认或拒绝；凭据不得进入记忆；自动识别不保证完美，需提供查看和人工删除。 |
| FR-28 | 本地记忆存储和故障处理。 | 以 SD 作为长期记忆主存储；缺卡、损坏、写满时明确暂停持久化且保护原数据，恢复流程不得静默格式化或用旧错位内容覆盖。 |
| FR-29 | 受控自主演化。 | 在授权、边界和用户锁定内逐步调整；用户可以查看依据、暂停、回滚且新行为能解释版本来源。 |
| FR-30 | 用户可管理自主程度和演化授权。 | 自主动作总开关、演化授权是分开的；暂停演化不自动暂停全部自主行为，反之亦然。 |

### 3.5 自定义唤醒词的完整产品流程

| ID | 需求 | 首版完成定义 |
|---|---|---|
| FR-31 | 第三方训练入口。 | App 给出兼容训练路线及数据/第三方条款、费用、可用性提示；用户主动在第三方网站生成模型，不在设计或未经许可时上传词语/音频/资料。 |
| FR-32 | 模型导入和兼容校验。 | 先检查包版本、目标板、前处理、输入输出、格式、大小和完整性；来源不可信，失败不替换已工作的模型；不执行模型附带代码。 |
| FR-33 | 有回退的激活。 | 两阶段安装、候选模型短测、确认激活；崩溃/重启/加载失败可回退上一可用模型，且缺卡或两候选槽损坏时回退设备内置的已验证 Hey Cube 默认模型。 |
| FR-34 | 用户体验反馈。 | App 明确告知生成/等待、安装、试唤醒和错误；词语、训练数据可能被第三方处理。离线生成和设备本机训练均非首版承诺。 |

## 4. 主要使用旅程

### 4.1 首次使用和换网

1. 设备启动自检，显示“未配置/需要联网”，展示用户可操作的配对入口；屏幕不展示服务凭据。
2. 用户在设备端发起并确认短时配对，App 扫描设备显示的配对信息，建立已认证的加密管理通道。
3. 用户输入 Wi-Fi 和自己的云服务配置，了解所选服务商将接收的数据；设备联网后校时并展示各服务状态。
4. App 引导选择角色，分别说明长期记忆和人格演化授权；**自主行为默认开启，勿扰默认不启用**，控制项可随时调整。
5. SD 缺失或不可信时显示“长期记忆未就绪”，不抹卡；其他联网能力按各自可用性使用。换网/换手机从设备物理入口重新建立安全关系，不把同一 Wi-Fi 当授权。

### 4.2 普通语音与用户控制

- 唤醒监听中检测目标词 → 采集本轮语音并进入 ASR → LLM 读取受限的工作上下文与当前角色下可用记忆 → 可发出能力提议 → 按回执生成回应 → 进入下一轮。
- 用户通过物理/UI 控制，或通过**该状态下已实现并验证的语音停止入口**发出停止时，先中断相关资源与尚未执行动作；旧网络结果即使晚到也不得再发声或复播。播放、思考、播报期间的语音停止可用性分别实测，不能默认所有状态均能识别；用户语音也不凭声纹证明身份，敏感管理转 App。
- 超时/结束后删除会话音频缓冲及临时工作上下文，停止会话录音并恢复唤醒监听；云端已接收数据的处理受服务商约束。
- 音乐播放与唤醒/播报并发需真实声学与资源验证；不能把当前代码里的参考抽头描述成已验证的 AEC。

### 4.3 角色和长期关系

1. 用户选预设、编辑自定义角色，或让 AI 起草后确认；保存后才产生角色版本。
2. 用户同意记忆与演化后，伙伴在该角色命名空间内按权限形成摘要和有边界的偏好变化；App 可展示来源和变化历史。
3. 用户纠正、删除或暂停时，后续检索、摘要、行动和在途任务立即遵守新代次；敏感记忆需独立确认。
4. 切换角色会结束旧会话、隔离旧工作上下文与在途结果；其他角色的记忆与演化配置不可自动拼入新角色。

### 4.4 自主行动

事件或周期触发 → 收集可信且有效的状态与候选 → 本地筛选，按需调用云模型提出动作及参数 → 验证当前授权和快照新鲜度 → 申请资源并执行 → 接收真实状态/结果 → 可解释地记录非敏感原因与观察。

例：在不打断用户、未被停止/禁用且网络可用的情况下，AI 可以决定搭话、播放音乐或改变表情；也可以选择不行动。播歌属于已注册 `music.play` 能力的一个动作，不要求为“无聊时播歌”建立独立的产品模块。

### 4.5 自定义唤醒词

App 说明兼容路线和第三方条款 → 用户自行在可用的在线服务训练并取得模型 → App 导入合规模型包 → 设备校验并在不覆盖现有模型的情况下安装 → 用户在真实环境试用 → 明确激活或回退。

**风险：**[voicute/onnx-wakeword 官方说明](https://github.com/voicute/onnx-wakeword)描述在线输入词语、可选真人录音后下载 `model.zip`；但当前公开材料未确认在线自定义下载一定包含可在 ESP32 使用的 TFLite/head，实际页面的费用、隐私与模型分发权也未核实。项目推理代码为 MIT，而训练管线另行托管且[维护者称暂不开源](https://github.com/voicute/onnx-wakeword/issues/3)。即使输出 ONNX 或 TFLite，也不等于能在 P4 上直接运行；模型、前处理、配套 head/流状态和算子必须整体匹配并经板测。路线不通时属于首版阻塞项，而不是偷偷删除自定义唤醒要求。

## 6. 非功能需求与评价口径

| ID | 要求 | 首版验收原则 |

## 8. 已知现状与设计边界

- 现有代码中已有混音、网络播放器、WakeNet、百炼级联、技能表、显示和 soul 原型；当前**普通对话并非已验证的连续多轮**，麦克风所有权与 provider 生命周期需重设计。
- 现有记忆在宿主合成测试中复现了恢复字段错位、后续改写可能丢失内容、提示块越界；不在真实用户 SD 上运行写入测试。具体证据见 `docs/15`。
- 现有 `SOUL_PROACTIVE` 并不覆盖所有本地自主行为；开机/重连播台和勿扰停台需要纳入统一动作策略。旧 P4“5/5”只代表短时正向观察，不代表长期、隐私或冲突验收。
- 现有卡顿、低概率黑屏、快线尾音噪音等遵循用户此前安排：先记录，功能开发后集中修复；但数据丢失、越界、越权和扩展门禁不能被当作可延期的体验问题。
- 当前没有在本次设计阶段连接设备、读取真实 SD 数据、调用付费模型、执行第三方训练或修改固件。
- **灵魂层 v2 定案(2026-11-19)**: 经精读 docs/11-23 → 需求逐条确认 → 二轮调研 → 选型确认, 情感/动机/性格/注入全套设计已定案于 [24](24_灵魂层v2设计定案.md); 实现按其 §7 分期(S1-S7)推进, 完成前本节各项"待实现"现状判断仍然有效。
