# 22 · 内存预算表

> 建立: 2026-11-18(预算批次)。起因: 三大内存根因全部源于"固定开销靠运行期堆碰运气"——
> PIE 栈落 RTCRAM(§52 表情 WDT)、hosted 15872B DMA 挤兑(§52 59min 网络失效)、
> voice/CLI 栈级联创建失败(§52 修复 A)。本表是**所有固定内存开销的唯一登记处**:
> 新增任务栈/静态缓冲/常驻大块, 先入表再写代码(cube_tasks.h 头部同款规则)。

## 0. 执法机制(三层)

| 层 | 时机 | 手段 | 失败语义 |
|---|---|---|---|
| 链接期 | 构建 | 静态占位(`.bss`/`xTaskCreateStatic`), map 可查 | 不存在失败 |
| 启动期 | app_main 尾 | `mem_budget_audit("boot")`(main/mem_budget.c) | 只告警不 abort(§52 修复 B: 内存硬断言=开机循环) |
| 按需 | CLI | `mem`(审计+分域水位) / `memcheck`(TLSF 完整性走查, §55.10) / `baseline n`(P50/P95/P99 采样) | 同上 |

CI/host_tests 侧: `tools/mem_budget_check.py` 解析双目标 map, 校验静态栈符号在位 + .bss 不越预算(§7)。

## 1. 物理内存地图(P4C5, ESP32-P4 @ 768KB HP SRAM + 32MB PSRAM)

| 区域 | 地址 | 容量 | 去向 |
|---|---|---|---|
| HP SRAM | 0x4FF00000 | 768KB | iram0.text 110KB + dram0.data 39KB + dram0.bss **222KB**(含 §3B 静态栈) + 剩余为堆 |
| RTCRAM (LP SRAM) | 0x50108000 | 31KB | **v6.1 起 ~27KB 静态定置给非 DMA/非 PIE/非实时任务栈**(§3B); 余 ~3.9KB 入堆(`ALLOW_RTC_FAST_MEM_AS_HEAP=y`); 无 DMA caps、PIE 不可写(§52 修复 A 回滚教训) |
| PSRAM | 0x46000000 | 32MB | §4 预算; 经 L2 cache 256KB(独立硬件, 不占 HP SRAM) |
| 内部独占兜底 | — | 8KB | `SPIRAM_MALLOC_RESERVE_INTERNAL=8192`(小粒度内部独占分配的保底) |

## 2. 放置判定规则(新开销按此决策, 自上而下第一条命中即止)

1. **DMA 外设要读写**(SDIO/SPI/I2S/DSI 描述符) → `MALLOC_CAP_INTERNAL|MALLOC_CAP_DMA`(HP SRAM; RTCRAM 无 DMA)。
2. **执行 PIE 指令**(EFC 解码链) → 只允许 taskLVGL(docs/06 §9.5 不变量)。
3. **实时音频路径**(prio≥18: mixer/voice) → 内部 SRAM(cache miss 抖动不可接受)。
4. **会走 flash 写路径的任务**(NVS/配对证书/OTA) → 栈必须内部: PSRAM 栈在 cache 关断窗口触发
   `esp_task_stack_is_sane_cache_disabled` 断言(批次 20 pairsrv 板上实证)。
5. **网络/文件读/解析类**(无 flash 写、无 PIE) → PSRAM(player/faceload/skpf/pstart/psoul/psnsd 实证口径,
   2026-11-10 起)。
6. **非实时 >4KB 缓冲** → 默认 PSRAM。
7. **常驻且大小固定** → 静态(`.bss` 数组或 `xTaskCreateStatic`); 大小运行期才知道才进堆。
8. **常驻固定栈且非实时/非 DMA/非 PIE** → RTCRAM 定置(`__attribute__((section(".rtc.bss")))`,
   P4 窗口 ≤28KB; v6.1 板上实证——v6 曾把全部静态栈塞 HP DRAM, dma largest 崩至 8704 →
   taskLVGL 创建失败 → TLSF 断言 boot loop)。P4 无 RTC_DATA_ATTR 宏, 用原生段属性。

## 5. 实测基线与待补

**v5(f1d0482f, 2026-11-18 1h 回归, 转换前)**:
- app_main: largest internal=155,648
- pre_ui: largest internal=31,744 / dma=25,600
- startup complete: 内部 free≈26.6KB(30509027−30482404), psram free≈30.4MB
- ⚠ 稳态 dma_largest 25.6KB 距 16KB 红线仅 ~9KB——HLS 启动一压即穿(§52 根因的定量印证)

**v6(5a52de3, 2026-11-18 上板)——失败存档**: 全部静态栈塞 HP DRAM(.bss 163,280→221,776) →
pre_ui dma largest 崩至 **8,704** → taskLVGL(20480, DMA caps)创建失败 → UI 降级 → 后续饥饿
路径触发 TLSF 断言 → **boot loop**(每 ~6s 复位)。教训: v5 的动态栈(INTERNAL|8BIT)实际有
~30KB 落在 RTCRAM 堆垫上, "栈静态化总量守恒"的假设忽略了**放置区域**——HP DRAM 才是 DMA
池的唯一来源, 多塞 1KB 静态就少 1KB dma_largest。

**v6.1(修正后上板实测)**:
- startup complete: 内部 free=**39,327**(较 v5 +12.7KB ≈ aitts/aimic 移 PSRAM 的 12.3K, 对账吻合)
- **dma largest=23,552**(LVGL 20,480 已分配之后的稳态值; v5 的 25,600 是 LVGL 分配前)
- psram free=30,470,212; boot 审计三红线全 PASS; 52s 零错误(voice/mixer 健康)
- **1h 浸泡(docs/19 §55.6)**: 59min 死亡场景完整复现(点火 t=58.4min 与 v5 精确一致)并存活,
  ping 370/370; HLS 启动再未击穿 16KB dma 红线(唯一余波=一次 TLS 握手瞬时失败)
- **×10 按需压测(docs/19 §55.7)**: stop→radio×10 全通; HLS 窗口 dma_largest 实测
  16,384~17,408(距 15,872 红线最薄 ~0.5KB——A1a 加固的空间); 电台期 HLS 合法占 ~2MB PSRAM

**待补**: DSI fb 实占、HLS 启动瞬时 dma_largest(P1 前后对照)、S31 下限校准(现为保守哨兵;
S31 .rtc.bss=8192 全量占用待板上复核)。

## 6. S31 摘要

- 物理层: 无 hosted(WiFi 原生, 协议栈本机), BT 控制器+Bluedroid ~80KB 常驻; 内部预算比 P4 更紧。
- 本批同样受益: 8 处静态栈 + 6 处 PSRAM 瞬态已在 build-s31 验证(s_cli_stack/s_mixer_stack 等符号在位, map bss=0x2b720)。
- S31 下限表(membudget.c)为保守哨兵, 首次上板 `mem` 采样后回填。

## 7. CI 校验(tools/mem_budget_check.py)

- 双目标 map 解析: §3B HP DRAM 静态栈符号在位且尺寸正确; .rtc.bss 总量在 §3B 窗口内
  (P4 26,624~30,720 / S31 6,144~9,216);
- dram0.bss ≤ 256KB(P4C5)/192KB(S31) 预算上限(超限=有失控静态增长);
- 任何 >16KB 新 .bss 单体会被列出供人工审(入表 or 移 PSRAM)。
